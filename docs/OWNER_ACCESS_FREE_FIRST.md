# Owner access and free-first testing

Current operating mode: technical observer and owner dashboard, LIVE OFF.
Do not enable a paid provider, attach billing, or add a paid fallback for this test phase.

## Two different secrets

- Owner token authenticates the existing dashboard. It is generated by the deployment's owner-access bootstrap, not an AI vendor. Retrieve the existing initial private token on the authorized VPS; do not commit or paste it into an issue, URL, or public page. If it no longer matches the enabled owner policy, rotate through the documented owner-access procedure.
- Model API key authenticates an external language-model provider. The technical engine and dashboard do not require it. No external language model is configured in the current test deployment.

## Free options

Keep the current no-model mode as the default until a free endpoint is verified.
A provider free tier still needs an account and key, has quotas and data-handling terms, and is not unlimited local inference. Do not attach a billing account to bypass its quota.
Local inference can use an OpenAI-compatible loopback endpoint without a provider key. It still needs a suitable host and installed model. Audit OS, RAM and CPU/GPU first; do not replace active VPS components to make room for a model.
Do not treat a Godmode client or agent wrapper as a model provider without checking the specific project and its backend.
